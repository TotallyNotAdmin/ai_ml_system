# AI_USAGE

AI-инструменты использовались как ассистент при проектировании и подготовке PoC. Финальные архитектурные и продуктовые решения принимались человеком на основе требований кейса.

## Где AI помогал

### 1. Понимание задачи и декомпозиция

AI помогал разложить кейс на части:

- hot path и async path;
- классификация;
- риск;
- retrieval;
- LLM draft;
- monitoring;
- privacy и safety.

Это помогло быстро сформировать структуру репозитория и список артефактов.

### 2. Проектирование архитектуры

AI предлагал варианты pipeline:

- classifier → router → LLM;
- retrieval-augmented generation;
- fallback-сценарии;
- разделение быстрого и медленного контура.

Часть предложений была использована, но ключевое решение — не ставить LLM на hot path — было принято из-за требований к latency, стоимости и надёжности.

### 3. Выбор ML/LLM-подходов

AI предлагал сразу использовать heavy LLM и embeddings для всех задач. Это было отклонено для PoC, потому что:

- нужен быстрый локальный запуск;
- нет реального датасета;
- важно показать безопасность и управляемость;
- правила дают понятный baseline.

В итоге выбраны:

- правила для риска;
- keyword scoring для темы;
- упрощённый lexical retrieval;
- mock LLM.

### 4. Разработка PoC

AI помогал генерировать каркас кода, тесты и документацию. После этого код дорабатывался и упрощался вручную, чтобы PoC запускался без внешних зависимостей.

### 5. Написание тестов и документации

AI помогал формулировать smoke-тесты и структуру README.

### 6. Поиск рисков и edge cases

AI подсказывал возможные риски:

- prompt injection;
- PII leakage;
- LLM outage;
- cost explosion;
- ложный auto-close.

Эти риски были отражены в `docs/risks-and-ops.md` и `SELF_REVIEW.md`.

## Где предложения AI были отклонены

1. **Отправлять весь тикет в LLM для классификации**
   - Отклонено из-за PII, latency и стоимости.
   - Заменено на локальный hot path без LLM.

2. **Автоматически закрывать все типовые тикеты**
   - Отклонено из-за риска ошибок.
   - Добавлены high-risk категории, confidence threshold и KB match.

3. **Использовать внешний LLM API по умолчанию**
   - Отклонено, чтобы PoC был воспроизводим без ключей и сети.
   - Добавлен mock LLM и fallback.

## Примеры ошибок AI

### Ошибка 1: Небезопасная рекомендация отправлять сырые тикеты в LLM

AI предложил передавать тело тикета в LLM без предварительной обработки. Это могло привести к утечке PII.

**Как обнаружено:**
Проверка требований privacy и анализ сценария с картой и email.

**Как исправлено:**
Добавлен модуль `pii.py`, который маскирует email, карты, телефоны и CVV/CVC перед LLM и логом.

---

### Ошибка 2: Предложение использовать LLM для принятия финального решения

AI предлагал, чтобы LLM сам решал, закрыть тикет или эскалировать.

**Как обнаружено:**
Это нарушает требование управляемости и аудируемости.

**Как исправлено:**
LLM используется только для генерации черновика. Решение принимает детерминированный router на основе риска, confidence и KB match.

---

### Ошибка 3: Хрупкие regex для PII

AI сгенерировал слишком широкие regex, которые могли матчить номера заказов, даты или случайные последовательности цифр.

**Как обнаружено:**
Ручная проверка и тесты на mock-тикетах.

**Как исправлено:**
Regex упрощены и ограничены более явными паттернами: email, банковская карта, российский телефон, CVV/CVC. В документации указано, что в production нужен NER/DLP.

---

### Ошибка 4: Слишком общая документация

AI сначала писал общие фразы про «использовать мониторинг и observability», без конкретных метрик.

**Как обнаружено:**
Review против требований задания.

**Как исправлено:**
Добавлены конкретные метрики, алерты, бизнес-показатели и критерии остановки пилота.

## Итог

AI ускорил создание структуры, документации и базового кода, но ключевые решения по безопасности, стоимости, latency и human-in-the-loop принимались человеком.
